## 2. What GRP is

A score in [0,100] measuring how much geopolitical premium is being priced into crude and products for one **theatre** (v1: Gulf — Kharg, Hormuz, Fujairah, Bab-el-Mandeb, Suez), updated every 30 minutes, decomposed so the author and the sub-agents can say how much of a price move is *headline* and how much is *barrel*, and can call the **fade** as well as the escalation.

### 2.1 Components (all in [0,1])

| Component | Measures | Spec |
|---|---|---|
| `escalation` | decayed mass of hostile events on the tape | 28.03 → 28.08 |
| `taco` | credibility of the dominant actor's threats (threat → follow-through vs walk-back) | 28.08 |
| `airspace` | NOTAM closures on watched FIRs, government/military aircraft movements, hub departure collapse | 28.04 → 28.08 |
| `physical` | AIS anomalies in geofenced boxes + EIA Gulf-origin imports / SPR / utilisation | 28.05, 28.06 → 28.08 |
| `crowded` (bool modifier) | managed-money length at 2y ≥ p80 with curve outrunning physical | 28.07 |

### 2.2 Formula (config-driven, versioned)

```
GRP = 100 × ( w_e · escalation · taco_dominant
            + w_a · airspace
            + w_p · physical )
      × (1 − crowded_penalty · crowded)

w_e = 0.40  w_a = 0.25  w_p = 0.35  crowded_penalty = 0.30
regimes: calm < 25 ≤ elevated < 50 ≤ stressed < 75 ≤ crisis
fade = (escalation dropped ≥ 0.15 over 48 h) ∧ (taco_dominant < 0.40) ∧ crowded
```

Every stored score carries `model_version`. Weights change only through `config/model.yaml` + a version bump.

## 5. Repo conventions this module must follow

1. **One schema per module.** `grp` writes only to schema `grp`. It reads `eia`, `markets`, `news` (if present). The one permitted write outside `grp/` is adding series IDs to the `eia` scraper's series list (28.06).
2. **Jobs are idempotent.** fetch → validate (Pydantic v2) → upsert (`ON CONFLICT DO UPDATE`) → write `grp.feed_status`. Safe to re-run any job at any time.
3. **Shared db helper.** Use the repo's existing `db/` connection + upsert helper. If it lacks a batch upsert, add one there and note it in `ARCHITECTURE.md`; do not write a second connection layer inside `grp/`.
4. **Secrets are env vars.** Every key in `.env.example` with a comment. Never read config from code constants.
5. **Logging.** One structured JSON line per job run: `{"job","theatre","rows","ms","status","error"}`. Match the repo's logger.
6. **Errors surface.** Any unhandled exception → `feed_status.last_error` written → exit code 1. Never swallow.
7. **No live network in tests.** All providers mocked from `grp/tests/fixtures/`.
8. **Python 3.11+, type hints.** Deps: `httpx`, `pydantic>=2`, `sqlalchemy>=2`, `shapely`, `websockets`, `sentence-transformers` (CPU), `matplotlib`, `pyyaml`, `anthropic`. Add to the repo's dependency file per its convention (pyproject / requirements per sub-project).
9. **Sessions.** ≤1 h weekdays, 3–4 h weekends. Stop at each phase boundary in 28.11, update `ARCHITECTURE.md`, report.
