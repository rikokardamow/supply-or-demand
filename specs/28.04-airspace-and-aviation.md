# Spec 28.04 — Airspace and Aviation Early Warning

Three feeds, three jobs, one score term (`airspace`, computed in 28.08 §4). The thesis: airports and airlines get warned before the wire does — NOTAMs, government aircraft movements and departure collapses lead headlines.

---

## 1. NOTAMs — `ingest/notam_icao.py` (primary), `ingest/notam_faa.py` (optional), `jobs/job_notam.py` (every 15 min)

### 1.0 Source decision
The FAA NOTAM API on api.faa.gov is not obtainable for non-US applicants, so the **primary source is the ICAO API Data Service** (api.icao.int / applications.icao.int/dataservices). ICAO pulls from the FAA's Defense Internet NOTAM Service (DINS), which carries worldwide NOTAMs including all eight Gulf/Israel FIRs, and offers two endpoints: *Realtime NOTAMS* (by a list of ICAO locations, live) and *Stored NOTAMS* (by state/location, refreshed every 3 h, searchable by Q-code and keyword). Access is an ICAO portal account plus a pay-per-call bundle — cheap at our volume (8 FIRs every 15 min ≈ 800 calls/day if one location per call; pass all locations in one call where the endpoint allows and it drops to ~100/day).

`ingest/notam_icao.py`: `GET {base_url}{realtime_path}?api_key=$ICAO_API_KEY&format=json&locations=OIIX,ORBB,OKAC,OBBB,OMAE,OOMM,OEJD,LLLL` → JSON array of NOTAM records with fields along the lines of `id, location, StateCode, StateName, message (ICAO raw format), startdate, enddate, all (full text), Qcode, series, type, criticality` — **verify field names against the portal's sample response on first call and pin them in a comment.** Parse the raw ICAO NOTAM (`Q) ... A) B) C) D) E) F) G)`) with a small parser: `A)` location, `B)`/`C)` effective from/to (`YYMMDDHHMM`, `PERM`), `E)` text, `Q)` line → FIR, Q-code, lower/upper limits, centre coordinates + radius (`ddmmNdddmmE rrr`) → build `bbox` from the circle. Q-codes map to severity before the keyword rules: `QRTCA`/`QRPCA` (restricted/prohibited area activated) → 4, `QRDCA` (danger area) → 4, `QARLC`/`QRACA` (airspace closed) → 5, `QNGAS`/`QGAXX` (GPS/GNSS) → 3, `QFALC` (aerodrome closed) → 3; else keyword rules from config.

If the Realtime endpoint is unavailable on your bundle, use Stored NOTAMS with `states=IRN,IRQ,KWT,BHR,ARE,OMN,SAU,ISR` on the same cadence (3-hour freshness is acceptable; flag it in `feed_status.last_error_msg` as `"stored mode"`).

**Do not scrape DINS directly** (`notams.faa.gov/dinsQueryWeb`): its terms state it is not designed for server-level access or screen scraping. It remains useful for manual eyeballing only.

**Secondary/complementary signal that needs no NOTAM feed at all:** FIR traffic collapse from OpenSky (§2 states already fetched). Count airborne aircraft per FIR bbox each 10-min poll, keep a 30-day same-hour baseline exactly as in §3, and treat `z ≤ −2.5` for ≥ 2 consecutive polls as an `airspace` event, severity 3, `meta.source='adsb_fir_count'`. This costs zero extra API credits and catches closures the NOTAM lags. FIR bboxes: add `firs[].bbox` to `theatre_gulf.yaml` (rough rectangles; Tehran FIR ≈ 44–63.5E / 25–40N, Baghdad ≈ 38.8–48.8E / 29–37.5N, Emirates ≈ 51.5–57E / 22.5–26.5N, Muscat ≈ 52–63E / 16.5–26.5N, Jeddah ≈ 34.5–55E / 16–32N, Bahrain ≈ 48.5–53E / 24–28N, Kuwait ≈ 46.5–49E / 28.5–30.1N, Tel Aviv ≈ 33.5–35.9E / 29.4–33.5N — tighten later).

### 1.0a FAA NOTAM API (optional, `enabled: false`)
Kept only for the case where FAA developer-portal access is later granted. Same normalisation; details below.

### 1.1 Auth and request

Register an app on the FAA developer portal (NOTAM API) → `client_id`, `client_secret`. (Not currently obtainable for non-US applicants — see §1.0.)

`GET https://external-api.faa.gov/notamapi/v1/notams`
Headers: `client_id: $FAA_NOTAM_CLIENT_ID`, `client_secret: $FAA_NOTAM_CLIENT_SECRET`
Params per FIR: `icaoLocation=<FIR icao>`, `responseFormat=geoJson`, `pageSize=50`, `pageNum=1..`, `sortBy=effectiveStartDate`, `sortOrder=Desc`. Optionally `effectiveStartDate=<since ISO>` to narrow.

One request per FIR per run (8 FIRs → 8 calls/15 min, well inside limits). If the FAA feed does not carry a given foreign FIR (coverage of non-US NOTAMs varies), fall back to `locationLatitude/locationLongitude/locationRadius` (nautical miles, max 100) centred on the FIR's main airport and note the gap in `feed_status.last_error_msg` without failing.

### 1.2 Response shape (GeoJSON)

```
{ "pageSize", "pageNum", "totalCount", "totalPages",
  "items": [ { "type":"Feature",
               "properties": { "coreNOTAMData": { "notam": {
                    "id","number","type","issued","affectedFIR","selectionCode","location",
                    "effectiveStart","effectiveEnd" (ISO or "PERM"),"text","classification","accountId",
                    "lastUpdated","icaoLocation","coordinates","radius" },
                 "notamTranslation":[{"type","formattedText"}] } },
               "geometry": { "type":"GeometryCollection"|"Polygon"|..., ... } } ] }
```

### 1.3 Normalise → `grp.notams`

- `id = notam.id`, `number`, `fir = affectedFIR or icaoLocation`, `issued_at = issued`, `effective_from = effectiveStart`, `effective_to = null if "PERM" else effectiveEnd`, `classification`, `text = text.upper()`.
- `keywords` = every `notam_keywords` term found in `text`.
- `severity` from `notam_severity_rules` (first match on `any` list; default 1).
- `geom` = first Polygon in `geometry` if PostGIS available; `bbox` computed from all coordinates in `geometry` (or from `coordinates` + `radius` as a square) always.
- Upsert on `id`; re-fetching the same NOTAM is a no-op except `fetched_at`.

### 1.4 Event creation

For a NOTAM **not previously seen** with `severity ≥ 3` and `effective_from ≤ now + 48 h`:
`insert_event(type='airspace', actor=fir.state, target=null, severity, source_tier=1, confidence=0.95, summary=f"NOTAM {number} {fir}: {first 120 chars of text}", first_seen=issued_at, meta={notam_id, keywords, effective_from, effective_to})`; set `notams.event_id`. Fire alert `airspace_closure`.

### 1.5 Active set for scoring

`active_notams(now)` = rows where `effective_from ≤ now` and (`effective_to is null` or `effective_to ≥ now`) and `severity ≥ 2`. Expired NOTAMs drop out of the score automatically.

## 2. OpenSky Network — `ingest/aircraft_opensky.py`, `jobs/job_aircraft.py` (every 10 min)

### 2.1 Auth (OAuth2 client credentials)

`POST https://auth.opensky-network.org/auth/realms/opensky-network/protocol/openid-connect/token`
Form: `grant_type=client_credentials&client_id=$OPENSKY_CLIENT_ID&client_secret=$OPENSKY_CLIENT_SECRET` → `{access_token, expires_in}` (~30 min). Cache token in-process; refresh at 80 % of `expires_in`. Header `Authorization: Bearer <token>` on API calls.

Credit budget: authenticated accounts get ~4,000 credits/day; a `states/all` call over a large bbox costs up to 4 credits. Track `credits_used_today` in `feed_status` from the `X-Rate-Limit-Remaining` response header when present; stop calling when `daily_credit_budget` is reached and mark the feed stale rather than failing.

### 2.2 States request

`GET https://opensky-network.org/api/states/all?lamin=10.0&lomin=20.0&lamax=62.0&lomax=65.0` (from `states_bbox`).
Response: `{"time": epoch, "states": [[icao24, callsign, origin_country, time_position, last_contact, longitude, latitude, baro_altitude, on_ground, velocity, true_track, vertical_rate, sensors, geo_altitude, squawk, spi, position_source, category], ...]}` — index positions are stable; `callsign` is 8 chars right-padded, strip it.

### 2.3 Aircraft database (weekly refresh)

`GET https://opensky-network.org/datasets/metadata/aircraftDatabase.csv` (~100 MB). Columns include `icao24, registration, manufacturericao, manufacturername, model, typecode, serialnumber, ... operator, operatorcallsign, owner, ...`. Load into a dict `icao24 → (typecode, operator, owner, registration)` and cache as `grp/store/aircraft_db.csv` (gitignored) holding only rows where `typecode ∈ watchlist.types` **or** `operator/owner` contains any `operator_contains` term — keeps the cache to a few MB. Refresh Sundays 03:00 UTC or when older than 8 days.

### 2.4 Watch-list filter

A state row is kept if:
- `callsign` starts with any `callsign_prefixes`, **or**
- `icao24` is in the cached aircraft DB (type ∈ `types` and operator/owner matches `operator_contains`, or type ∈ `{C32, C40, C17, C30J, E3CF, E3TF, R135, K35R, P8, E6}` regardless of operator).

Upsert to `grp.aircraft_positions` with `ts = time_position or last_contact`, `geofence` = first `airport_geofences` entry within `radius_km` (haversine on lon/lat), else null.

### 2.5 Landing detection → events

For each kept aircraft, compare with its previous stored position (last 30 min):
- **landed** := `on_ground = true` inside a geofence, **or** `baro_alt_m < 300` and `velocity_ms < 90` and `vertical_rate < 0` inside a geofence, and no `aircraft_landings` row for `(icao24, geofence)` in the last 6 h.
- Insert `grp.aircraft_landings`; `insert_event(type='aircraft', actor = nationality from callsign/operator (SAM/RCH/JAKE/HOMER/VENUS → US; RSD/RFF → RUSSIA; IRAN/IRA/IRC → IRAN; else OTHER), target = geofence state, severity = 3 + severity_boost (cap 5 → practically 3 or 4), source_tier=1, confidence=0.9, summary=f"{callsign or type_code} ({type_code}) landed {geofence.replace('_',' ')}", meta={icao24, registration, operator, origin_country})`. Fire alert `gov_aircraft_landing`.
- **Departure** from a geofence (previous inside/on_ground, now airborne outside): store in `meta` of the last landing event as `departed_at`; no new event.

### 2.6 Credits math

One `states/all` call every 10 min = 144 calls/day × ≤ 4 credits = ≤ 576/day. Delays (§3) add ~168/day. Total well under 3,500. Do not add per-aircraft track calls in v1.

## 3. Hub departure proxy — `ingest/delays_opensky.py`, `jobs/job_delays.py` (hourly)

### 3.1 Request

`GET https://opensky-network.org/api/flights/departure?airport=OMDB&begin=<epoch>&end=<epoch>` for each `airports_delay_proxy` entry, window = previous full UTC hour (max span 2 h per the API). Response: `[{icao24, firstSeen, estDepartureAirport, lastSeen, estArrivalAirport, callsign, ...}]`. Count = `len(response)`. 404 = no flights → count 0.

### 3.2 Baseline and z-score

For `(airport, hour_of_day, weekday)` over the trailing 30 days: `baseline_mean`, `baseline_std` (min std 1.0). `z_30d = (departures − baseline_mean) / baseline_std`. Upsert `grp.airport_delays`.

A **collapse** (`z_30d ≤ −2`) is the signal (airspace shut, carriers cancelling). Positive z is ignored. On the first collapse hour for an airport in a 6-h window: `insert_event(type='airspace', actor=OTHER, severity=2, source_tier=1, confidence=0.7, summary=f"Departures at {airport} {departures} vs baseline {mean:.0f} (z={z:.1f})", meta={airport, z, hour})`.

OpenSky coverage in the Gulf is partial (receiver density); the 30-day self-baseline absorbs that — never compare airports to each other.

## 4. Scoring inputs handed to 28.08

- `notam_term = max(severity/5 for active_notams)` else 0.
- `aircraft_term = max over landings in last 72 h of (1.0 if severity 4 else 0.5) × 2^(−age_h / 24)`.
- `delay_term = clip(max(−z_30d over hubs, last 3 h) / 3.0, 0, 1)`.
