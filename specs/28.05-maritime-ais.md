# Spec 28.05 — Maritime AIS Service

`grp/jobs/job_ais.py` is a **long-running process** (docker-compose service `grp-ais`; later a Railway always-on service), not a cron job. It holds one AISStream websocket, buffers tanker positions, flushes to Postgres every 60 s, runs anomaly detection every 15 min, and heartbeats `feed_status` every 5 min.

---

## 1. AISStream connection — `ingest/ais_aisstream.py`

Register at aisstream.io → API key.

Connect `wss://stream.aisstream.io/v0/stream` and send **within 3 s** the subscription message:

```json
{"APIKey": "$AISSTREAM_KEY",
 "BoundingBoxes": [[[lat_min, lon_min], [lat_max, lon_max]]],
 "FilterMessageTypes": ["PositionReport", "ShipStaticData"]}
```

**Note the order: AISStream bounding boxes are `[lat, lon]` pairs, not GeoJSON `[lon, lat]`.** Compute one box from the union of all theatre geofences + 0.2° margin (`GrpConfig.theatre.union_bbox`). Optionally pass one box per geofence instead (max 4 boxes per subscription on the free tier — verify; union box is the safe default).

Message envelope:

```json
{"MessageType": "PositionReport",
 "MetaData": {"MMSI": 123456789, "ShipName": "NAME", "latitude": 29.1, "longitude": 50.3, "time_utc": "2026-09-05 12:00:01.123 +0000 UTC"},
 "Message": {"PositionReport": {"Cog": 123.4, "Sog": 0.1, "TrueHeading": 120, "NavigationalStatus": 1,
             "Latitude": 29.1, "Longitude": 50.3, "Timestamp": 1, ...}}}
```

```json
{"MessageType": "ShipStaticData",
 "MetaData": {...},
 "Message": {"ShipStaticData": {"ImoNumber": 9000000, "Name": "NAME", "Type": 80, "Destination": "KHARG",
             "MaximumStaticDraught": 21.5, "Dimension": {"A":120,"B":130,"C":20,"D":30}, ...}}}
```

Parse `time_utc` with format `"%Y-%m-%d %H:%M:%S.%f %z UTC"` after stripping the trailing ` UTC`; fall back to receive time if parsing fails. `TrueHeading == 511` means unavailable → null. `Sog` in knots (1023 = unavailable → null). Length = `A + B`.

Reconnect on close/error with backoff 5 s → 10 → 20 → 60 (cap), reset on 10 min stable. Every reconnect re-sends the subscription. Log `{"event":"ais_reconnect","attempt":n}`.

## 2. In-process state

```python
static: dict[int, VesselStatic]              # mmsi → type, name, length, destination, draught, updated_at
last_kept: dict[int, datetime]               # mmsi → last position we persisted
buffer: list[VesselPosition]                 # flushed every 60 s
```

Keep a position when **all** hold:
1. `static[mmsi].ship_type ∈ tanker_ship_types` (if static unknown yet, keep for up to 30 min and drop retroactively if type turns out non-tanker — simpler: keep only once static is known; AISStream sends static every ~6 min).
2. `length_m ≥ min_length_m` (unknown → keep).
3. `now − last_kept[mmsi] ≥ position_keep_interval_min` **or** the geofence changed **or** `|Δheading| ≥ 90°` since last kept (so U-turns are not sampled away).

`geofence` tag = first geofence polygon containing the point (`store/geo.py`, shapely `Polygon.contains(Point)`, polygons prepared at load).

Flush: `upsert_vessel_positions(buffer)` (batch `INSERT ... ON CONFLICT (mmsi, ts) DO NOTHING`), `upsert_vessel_static(changed)`, clear buffer. Static upsert also detects **draught change** (§3.4).

## 3. Anomaly detection (every 15 min, over `lookback_hours = 6`)

Runs in the same process (`asyncio` task) against the DB, not the buffer, so it is restart-safe. Each anomaly is unique on `(mmsi, kind, ts)`; `ts` is the anomaly's onset so re-runs are idempotent.

### 3.1 `ais_off`
Vessels whose **last** position is inside any geofence and `now − last_ts > gap_minutes` (180), and no `ais_off` anomaly for that mmsi with `ts == last_ts`. Detail: `{last_geofence, last_lat, last_lon, gap_min}`. Onset `ts = last_ts + gap_minutes`.
Vessels that reappear close the gap implicitly; the anomaly stays as history.

### 3.2 `loiter`
Per vessel, per geofence with `expected_loitering: false`, contiguous run of positions with `sog_kn < loiter_speed_kn` lasting `≥ loiter_hours` (12). Onset `ts` = start of run. Detail `{geofence, hours, mean_sog}`. Anchorage-type geofences (`expected_loitering: true`) are excluded — waiting off Kharg or Fujairah is normal.

### 3.3 `uturn`
Inside `hormuz_tss` or `bab_el_mandeb`: two positions within `uturn_window_min` (60) whose `cog_deg` differ by `≥ uturn_heading_delta_deg` (150, circular difference) and `sog_kn ≥ 3` on both. Onset = second position. Detail `{geofence, cog_from, cog_to, minutes}`.

### 3.4 `draught_change`
On static upsert, if the vessel's last known position is inside `kharg_anchorage` (or any `expected_loitering` geofence) and `|new_draught − old_draught| ≥ draught_change_m` (2.0): anomaly with detail `{from, to, geofence}` — a loading/discharge signature. Onset = static `updated_at`.

### 3.5 Events from anomalies
- `ais_off` and `uturn`: `insert_event(type='vessel', actor=OTHER, target=null, severity=3, source_tier=1, confidence=0.8, summary=f"{name or mmsi} {kind} in {geofence}", meta={mmsi, kind, detail})`; set `vessel_anomalies.event_id`.
- **Clustering:** if ≥ 3 `ais_off` or `uturn` anomalies occur in the same geofence within 3 h, create **one** cluster event (severity 4, `meta.cluster_count = n`, `meta.mmsis = [...]`) and attach the individual anomalies' `event_id` to it instead of creating one event each. Fire alert `vessel_anomaly_cluster`.
- `loiter` and `draught_change` do not create events; they feed `ais_daily` only.

## 4. Daily aggregates — `ais_daily` (in `job_physical.py`, 05:00 UTC; also on demand)

For yesterday (UTC) per geofence:
- `tanker_count` = distinct mmsi with ≥ 1 position inside the geofence.
- `mean_sog_kn` = mean of positions' sog.
- `ais_off_count`, `loiter_count`, `uturn_count`, `draught_count` = anomalies with onset that day and that geofence.

Baselines for scoring (28.08 §5): 30-day mean/std per geofence per metric from `ais_daily`. Until 30 days of history exist, use whatever exists (min 7 days), and mark `physical` as `low_confidence` in `components.meta`… the `components` table has no meta column — add `physical_conf real` in 28.02 if needed; simpler: log it and let 28.08 down-weight `ais_term` by `min(1, days_available/30)`.

---

## 5. Heartbeat and health

Every 5 min: `feed_ok('aisstream', rows=positions_kept_last_5min)`. If no message of any kind received for 10 min while connected → force reconnect. Expose counters in the log line: `{"job":"ais","msgs":n,"kept":k,"tankers_tracked":t,"buffer":b}`.

`GET /grp/feeds` shows `aisstream` staleness from this heartbeat.

---

## 6. Row budget

Gulf tanker population in the union box ≈ 300–600 vessels; at 1 kept position / 5 min → ≤ 175k rows/day worst case, realistically ~40–60k. `vessel_positions` pruned at 90 d (28.02 §4) → < 1 GB steady state. If it exceeds 100k rows/day, raise `position_keep_interval_min` to 10 in config, not code.
